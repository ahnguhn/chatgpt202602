60초 카페 — 사용자 제공 캐릭터 버전
============================================================

[1. 실행 방법]
1) ZIP을 완전히 압축 해제하세요.
2) assets 폴더를 포함한 파일 구조를 그대로 유지하세요.
3) index.html을 브라우저로 여세요.
4) "카페 문 열기"를 누르면 게임이 시작됩니다.

설치, 인터넷, 서버 실행, 외부 라이브러리, CDN, 빌드가 필요 없습니다.
압축파일 미리보기 안에서 실행하지 말고 먼저 압축을 해제하세요.
일부 모바일 파일 앱은 HTML 미리보기에서 스크립트 실행을 제한합니다.
그런 경우 브라우저로 여세요.

[2. 이번 버전에서 바뀐 부분]
- 기존 CSS 도형 캐릭터를 사용자가 제공한 캐릭터 이미지로 교체했습니다.
- 캐릭터의 얼굴, 머리, 옷, 색상은 재생성하지 않았습니다.
- assets/character.jpeg는 제공받은 원본 파일의 사본입니다.
- 카운터 뒤에 캐릭터의 상반신이 보이도록 CSS로 크기와 위치를 조절합니다.
- 작은 화면에서도 주문 말풍선과 함께 볼 수 있게 반응형 크기를 적용합니다.
- 주문, 채점, 시간 제한, 재료 선택, 재시작 로직은 그대로 유지합니다.
- 온라인 이미지를 불러오지 않고 ZIP에 포함된 이미지만 사용합니다.

이미지 배경에 관한 참고:
제공된 JPEG에는 회색/흰색 바둑판이 그림의 일부로 포함되어 있습니다.
원본 자체를 편집하지 않고 CSS clip-path로 캐릭터 외곽을 따라 표시 영역을
조정하여 배경 노출을 줄였습니다. 픽셀 단위의 정밀 배경 제거 또는
진짜 투명 PNG로 변환한 결과는 아니며, 일부 가장자리에 원본 배경이
보일 수 있습니다. 원본 투명 PNG가 있다면 그것을 사용하는 편이 좋습니다.

[3. 파일 구조와 역할]
index.html
  시작/주문/종료 화면, 현황판, 재료 조작 버튼, 레시피 영역.
  캐릭터는 ./assets/character.jpeg를 상대경로로 불러옵니다.

style.css
  카페 배경, 메뉴판, 말풍선, 버튼, 반응형 배치, 각종 애니메이션.
  맨 아래 "사용자 제공 캐릭터" 구역에서 이미지 배치와 외곽을 조절합니다.

script.js
  게임 설정과 레시피, 재료 선택, 정답 판정, 채점, 타이머와 재시작.

assets/character.jpeg
  사용자 제공 원본 캐릭터 이미지. 폴더 이름과 파일 이름을 유지하세요.

README.txt
  실행 방법, 규칙, 수정 방법, 실제 점검 내용과 미확인 범위.

[4. 게임 규칙]
- 기본 제한 시간은 60초입니다.
- 주문에 맞는 재료를 고른 뒤 "음료 제출하기"를 누릅니다.
- 같은 재료를 다시 누르면 선택이 해제됩니다.
- 선택 순서는 상관없으며, 필요한 재료만 정확히 일치해야 정답입니다.
- 재료가 하나라도 빠지거나 불필요한 재료가 추가되면 오답입니다.
- 정답이면 100점과 성공 주문 1잔을 얻습니다.
- 정답 뒤에는 선택한 재료가 초기화되고 다른 음료가 무작위로 나옵니다.
- 오답이면 감점 없이 선택한 재료만 초기화됩니다.
  같은 주문을 다시 시도할 수 있습니다.
- 재료 없이 제출하면 재료를 선택하라는 안내를 보여 줍니다.
- "비우기"는 현재 선택한 재료를 모두 취소합니다.
- 시간 종료 후에는 조작이 잠기고 점수, 성공 주문, 재시작 버튼이 표시됩니다.
- 다시 시작하면 점수, 시간, 주문, 선택 재료, 안내를 초기화합니다.

기본 레시피:
아메리카노: 에스프레소 + 물
카페라테: 에스프레소 + 우유
아이스 라테: 에스프레소 + 우유 + 얼음

[5. 조작과 접근성]
- 마우스 클릭과 모바일 터치를 지원합니다.
- Tab으로 버튼을 이동하고 Enter 또는 Space로 누를 수 있습니다.
- 키보드 포커스 외곽선과 선택 상태의 색상/테두리/체크 표시를 제공합니다.
- 선택 상태는 aria-pressed에도 반영됩니다.
- 정답/오답 안내는 화면을 덮지 않는 별도 영역에 표시합니다.
- 작은 화면에서는 세로 스크롤로 전체 내용을 볼 수 있습니다.
- 움직임 줄이기 설정(prefers-reduced-motion)을 존중합니다.
- 글꼴과 재료 이모지 모양은 기기에 따라 조금 달라질 수 있습니다.

[6. 설정을 수정하는 위치]
script.js 맨 위에서 설정을 수정하고 UTF-8로 저장한 뒤 새로고침하세요.

게임 시간:
  const GAME_DURATION = 60;
  0보다 큰 초 단위 숫자를 사용하세요.
  소개 문구와 타이머도 이 값을 따릅니다. 게임 제목은 그대로입니다.

정답 점수:
  const CORRECT_SCORE = 100;
  정답 점수, 점수 안내표, 정답 효과에 함께 적용됩니다.

음료 레시피:
  const RECIPES = [...] 배열에서 수정하세요.
  name: 음료 이름
  ingredients: 필요한 재료 키 배열
  icon: 메뉴판 장식 이모지

예:
  { name: "아메리카노", ingredients: ["espresso", "water"], icon: "☕" }

사용 가능한 재료 키:
  espresso = 에스프레소, water = 물, milk = 우유, ice = 얼음

레시피는 하나 이상 남겨야 하고 재료 키는 중복 없이 넣으세요.
안내표도 같은 데이터에서 자동 생성됩니다.
새로운 종류의 재료를 추가하려면 INGREDIENTS 데이터와
index.html의 재료 버튼도 함께 추가하세요.

캐릭터 표시 크기와 위치:
  style.css 맨 아래 .character-image의 width와 top을 수정하세요.
  아래 @media 규칙은 화면 너비별 크기를 정합니다.
  clip-path는 현재 원본 캐릭터의 외곽에 맞춰져 있으므로,
  다른 캐릭터를 넣으면 수정하거나 제거해야 합니다.
  진짜 투명 PNG로 바꾸는 경우 이미지 경로를 수정하고
  clip-path를 none으로 변경하면 됩니다.

[7. 중복 실행 방지]
- 이벤트는 click만 등록해 마우스, 터치, 키보드를 함께 지원합니다.
- touchstart와 click을 함께 등록하지 않아 터치 이중 실행을 피합니다.
- Set으로 재료를 관리하여 중복 추가를 막습니다.
- 정답 직후 재료를 비워 연속 제출로 중복 채점되지 않도록 합니다.
- 시작/재시작 시 기존 interval을 해제합니다.
- 남은 시간은 performance.now()와 종료 시각의 차이로 계산합니다.
- 모든 입력 직전에도 종료 시각을 검사합니다.
- 애니메이션 완료 이벤트는 장식만 제거하며 점수나 시간을 바꾸지 않습니다.
- 새로고침 시 저장 없이 처음 화면으로 돌아갑니다.

[8. 실제 점검 결과]
Chromium + Playwright 자동화 검사 53개 항목 통과:
- 시작 화면 및 시작 전 조작 차단, 초기 상태
- 제공 캐릭터 원본 이미지의 정상 디코딩(PC/모바일, 1024 × 1024)
- 기존 CSS 캐릭터 제거, 새 이미지 1개 배치, CSS 외곽 클리핑 적용
- 시작 후 새 주문, 빈 재료 제출 안내
- 재료 선택/해제, 재료 비우기
- 불필요한 재료를 포함한 오답, 감점 없음, 같은 주문 유지, 선택 초기화
- 세 레시피를 역순으로 선택해 정답 처리, 점수/성공 수 증가
- 다음 주문 생성 및 선택 초기화, 연속 제출 중복 채점 방지
- 키보드 Tab 이동, Enter/Space 조작, 포커스 표시
- 실제 60초를 기다린 뒤 종료, 최종 400점/4잔 표시
- 종료 후 버튼과 함수 입력 차단
- 재시작 전체 초기화 및 중복 타이머 방지
- 종료 시각 경계의 입력 차단, 탭 복귀 시간 재검사 시뮬레이션
- 320~1440px의 9개 화면 너비에서 가로 넘침 없음
- 표시된 버튼의 너비와 높이 각각 44px 이상
- 움직임 줄이기 설정 존중
- 외부 네트워크 요청 및 브라우저 JavaScript 오류 없음
- 모바일 터치 선택/해제/정답 제출, 중복 이벤트 없음, 세로 스크롤

추가 정적 검사:
- node --check script.js 통과
- HTML에서 참조한 CSS/JS/JPEG 상대경로 파일 존재
- 제공받은 JPEG와 배포 JPEG의 SHA-256 일치(원본 변경 없음)
- ZIP 파일의 무결성 검사 통과


[9. 검사 방식과 확인하지 못한 부분]
- 검사 환경의 Chromium 보안 정책이 file:// 및 HTTP 탐색을
  차단하므로 index.html을 직접 열어 실행하는 통합 검사는 하지 못했습니다.
- 브라우저 기능 검사는 HTML/CSS/JavaScript 원문을 about:blank에
  주입해 진행했습니다. 이미지는 동일한 원본 JPEG 바이트를 테스트에서만
  data URL로 주입했습니다. 실제 배포본은 분리된 파일과 상대경로입니다.
- 이미지와 코드의 상대경로, 파일 존재 여부는 별도로 정적 확인했습니다.
- 일부 레시피/마감 경계/타이머 방어 검사는 테스트에서 주문, 종료 시각,
  함수 호출 등을 조작한 시뮬레이션을 포함합니다.
- 탭 복귀 검사는 종료 시각이 지난 상태에서 visibilitychange를 발생시킨
  시뮬레이션이며, 실제 백그라운드 탭 장기 정지는 미검증입니다.
- 모바일 검사는 Chromium의 터치 에뮬레이션으로, 실제 기기 검사가 아닙니다.
- 실제 iPhone/Android, Safari, Firefox, 스크린리더, 기기 절전/잠자기는
  검증하지 못했습니다.
- 레이아웃은 DOM 크기와 계산된 CSS로 검사했습니다.
  사람이 화면 전체와 캐릭터 외곽을 눈으로 최종 검수한 것은 아닙니다.
- 애니메이션의 기기별 렌더링과 주관적인 시각적 인상은 미검증입니다.
