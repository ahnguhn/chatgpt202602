기록 안내: 아래는 사용자 요청을 AI가 구체화한 작업용 지시이며 사용자가 직접 작성한 원문으로 주장하지 않습니다.
사용자 실제 요청: 첨부된 파일에 지시문을 따라서 완성해 줘

[최초 프롬프트]
A유형 자유주제 웹 응용 프로그램으로 ‘과제온: 대학생 과제 우선순위 플래너’를 제작해 줘.

1. 목적과 사용자
여러 과목의 마감일이 겹쳐 먼저 할 과제를 결정하기 어려운 대학생이, 과제를 입력하고 점수·남은 시간·완료율을 확인하도록 한다.

2. 기술 및 제출 조건
HTML·CSS·JavaScript만 사용하고 외부 라이브러리, 외부 폰트 요청, 서버 API를 사용하지 않는다.
CSS와 JavaScript를 포함한 단일 index.html로 작성한다. localStorage, sessionStorage, 쿠키, 파일 저장 등 데이터 저장 기능을 사용하지 않는다. 입력 데이터는 메모리에서만 유지하고 새로 실행하면 빈 목록으로 시작한다.
실행에 필요한 외부 이미지는 사용하지 않는다. PC·모바일 브라우저에서 동작하도록 한다.
제출물은 index.html이 들어 있는 프로그램 폴더의 ZIP과 별도 과정기록 PDF로 구성한다.

3. 입력 데이터
과제명: 필수, 앞뒤 공백을 제외한 1~60자.
과목명: 선택, 최대 30자, 비어 있으면 ‘과목 미지정’.
마감일: 필수, 실제 존재하는 날짜, 2000-01-01~2100-12-31.
중요도: 낮음 1 / 보통 2 / 높음 3.
예상 시간: 필수, 0.5~100시간, 0.5시간 단위.
기준일: 처음에는 사용자의 로컬 오늘 날짜. 사용자가 바꿀 수 있으며 마감일과 같은 날짜 범위로 검사한다.

4. 계산 규칙
남은 일수는 마감일과 기준일의 달력 날짜 차이로 계산한다.
점수 = 중요도 × 20 + 긴급도.
긴급도: 마감 지연 50, 당일 45, 1~3일 35, 4~7일 20, 8일 이상 5.
기본 정렬은 미완료 먼저, 점수 내림차순, 동점이면 마감일 오름차순, 다시 동점이면 최초 추가 순서.
완료 항목은 점수를 ‘—’로 표시하고 항상 목록 하단에 둔다.
남은 과제 수·3일 이내 마감(지연 포함) 수·미완료 예상 시간 합계·완료율을 전체 데이터로 계산한다.
완료율은 완료 수 / 전체 수 × 100을 정수 반올림하며 전체가 0이면 0%로 한다.

5. 조작 및 오류 처리
추가, 기존 과제 수정과 취소, 완료 및 완료 해제, 개별 삭제, 전체 초기화를 제공한다.
삭제와 초기화는 확인창에서 취소할 수 있게 한다. 수정은 기존 항목을 덮어쓰되 완료 상태와 최초 추가 순서를 보존한다.
전체/진행 중/완료 필터와 우선순위/마감일/시간 정렬을 제공한다.
예시 과제 4개는 사용자가 버튼을 눌렀을 때만 불러오고, 기존 데이터가 있으면 중복 추가하지 않는다.
빈 값·공백 제목·날짜 오류·시간 범위·시간 단위 오류는 구체적인 한글 안내와 입력 위치 포커스로 처리한다.
HTML처럼 생긴 입력도 실행하지 않고 문자로만 표시한다.
데이터 미저장 안내와 빈 목록 안내를 표시한다.

6. 화면
차분한 초록색과 밝은 배경을 사용한다. 상단은 제목·기준일과 4개 통계, 본문은 입력 폼과 과제 목록으로 나눈다.
PC는 2열, 모바일은 1열로 표시하고 가로 스크롤이 생기지 않게 한다.
입력 label, 키보드 포커스 표시, 버튼 설명, 상태 알림, 계산 기준 안내를 포함한다.

[수정 프롬프트]
최초 버전을 Chromium으로 실행한 결과, 아래 두 문제가 실제로 재현되었다.
화면 색상·구성, 점수 규칙, 반응형 배치와 나머지 기능을 유지하면서 수정해 줘.

문제 1: 공백 제목이 등록됨.
재현: 기준일을 2026-11-12로 설정하고, 과제명에 공백 3개, 마감일에 2026-11-13, 중요도 높음, 예상 시간 2를 입력한 뒤 추가한다.
실제: 제목이 비어 보이는 과제 1개가 생성된다.
기대: 앞뒤 공백을 제거한 제목을 검사하고, 공백뿐이면 ‘과제명을 1~60자로 입력해 주세요.’를 표시한다. 목록과 통계는 바뀌지 않아야 한다.
수정: 입력을 읽을 때 trim()을 적용하고, 정리한 제목을 저장한다.

문제 2: 수정 후 동점 과제의 최초 추가 순서가 바뀜.
재현: 동일한 마감일 2026-11-13, 중요도 높음, 예상 시간 2로 ‘먼저 추가한 과제’와 ‘나중에 추가한 과제’를 순서대로 등록한다. 첫 항목의 수정 버튼을 누르고 내용 변경 없이 저장한다.
실제: ‘나중에 추가한 과제’가 먼저 표시된다.
기대: 수정은 같은 항목을 갱신하는 것이므로 최초 추가 순서가 유지되어야 한다.
수정: 수정 시 기존 id를 유지하고, 신규 추가일 때만 nextId를 증가시킨다. 기존 완료 상태도 유지한다.

두 재현 사례를 다시 검사하고, 정상·빈 값·경계값·삭제 취소·완료 전환·정렬·모바일 배치를 회귀 테스트해 줘.
